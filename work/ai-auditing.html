How I scaled my content design expertise into an agent

How do you scale one content designer across an entire product surface?

When you're the only content designer on a team, you have to make choices about what gets your attention. There are only so many hours, and the work that's in front of you always feels more urgent than the work that's been sitting untouched for years.

On Facebook Core Identity, that untouched work was everywhere. Profile is a sprawling surface with decades of accumulated strings. I could do the current projects well, or I could do the audit work, but I couldn't do both. I built an agent AI that could help me keep an eye on all surfaces at once.

Tools

Claude Code, internal agents for analytics and diff creation

Surface

Facebook Profile

Team

Core Identity (sole content designer)

Core content problem

Without a way to systematically surface outdated, inconsistent or incorrect content across Profile, problems stayed invisible until someone happened to stumble across them. I needed a way to monitor the codebase continuously, flag issues by severity and generate draft fixes I could review, without that work consuming all of my time.

The challenge was to build an agent with enough content design judgment to ensure genuinely useful rather than superfluous output.

My approach

I created an agent I named Spruce, built with Claude Code and connected to internal tools for analytics and diff creation. Prompt architecture was key so Spruce could decide effectively what to care about most and what to do about it. I defined severity levels for content issues so Spruce could triage flagged issues. The prompt went through 23 test rounds before I was confident in its accuracy.

I also designed Spruce to hand off work to other agents rather than try to do everything itself. For example, it would call out to separate tools to check string liveness and pull daily view counts before deciding whether to flag it.

One constraint I held firm on: Spruce submitted diffs as drafts and didn't land code directly to ensure accuracy and protect the time of engineers and designers.

How Spruce works

Severity rubric

High severity

Blocks assistive technology or translation. Vague or misleading CTA labels. High-traffic surface.

Moderate severity

Inconsistent terminology or lower-traffic surface.

Low severity

Casing, punctuation or style drift that doesn't block comprehension.

Results

Over the prompt lifecycle, Spruce scanned 30 Profile directories weekly, giving me continuous visibility, and diff accuracy improved by 54%. Coverage across Profile increased in a way that would have been impossible for one person to achieve manually.

One unexpected outcome was improved collaboration with eng. Engineers engaged with my diffs in ways that opened up conversations we wouldn't have had otherwise.
